# Design System: BYO CLI

## Overview

**Creative North Star: "The Showroom"**

byocli.com is a product page for a command-line tool, built the way a hardware product page is built. The ground is white, broken into bands of white and pale grey with one black band at the end for getting started. Each band holds one idea: a large sentence-case headline that ends in a full stop, a one-line grey subhead, and then the idea itself carried by words set in a grid, a row of pills, flat tiles or a single paragraph of large type. The landing page is marketing only: it shows no commands, code, transcripts or file lists, and every section ends in one link into the documentation that holds the detail. The product shot is the hero's flow figure: your software, a dark window-shaped frame that stands for the CLI, and the three audiences it serves. That frame is the one dark object on the light page and the one thing lit like a product on a showroom floor, with a single soft shadow under it and nothing else casting one.

The treatment is quiet and exact. Inter carries everything a person reads; Geist Mono carries the three places a person would type, the install one-liner, the grammar line on the docs index and the documentation's code, with syntax colouring switched off so a command is one colour. The brand navy is the only colour that acts: buttons, links, the current docs page, the selection highlight, the focus halo. The brand green survives only in the logo and as the prompt of the install command, where it reads as the terminal's own colour rather than as a brand accent. Surfaces are pills, 28px tiles and a 14px window frame; there are no gradients in type or fills, no eyebrows above headlines, no card rows with icons and no metaphor world.

Density is generous between ideas and tight inside a component. Sections pad 72 to 128px, a section head sits centred at 760px, and the bento's five grey tiles on the white band vary in width (3+3, then 2+2+2 of 6 columns) so a row reads as a composed spread rather than a grid of equals. The documentation takes a reference-manual register: a plain-text left rail with the current page in navy, a white reading column, light grey code blocks with dark text, hairline tables. The not-found page borrows the landing page's section head and actions row and nothing else. The direction is the category standard executed at the highest grade; the earlier pegboard metaphor world was rejected and nothing of it carries over.

**Key Characteristics:**
- White ground with alternating pale grey bands and one black install band; each band carries exactly one headline and one idea, and ends in one link into the docs.
- The product is shown once, as the hero's flow figure: hairline pills and a dark window-shaped frame joined by 1px hairlines; the frame is the only dark object and the only shadow on the page.
- Inter Variable for reading in sentence case with tight negative tracking; Geist Mono for the install command, the docs grammar line and documentation code, in one colour.
- One accent, the brand navy, on anything that acts; the brand green only in the logo and as the install prompt.
- Pill buttons, 28px flat tiles, a 14px window frame, a frosted 48px nav; borders are 1px hairlines and appear only where tone cannot separate.
- Every press target is at least 24px tall, every focus is a 3px halo at 3px offset, and the install switch is a real tablist with arrow keys.
- One authored motion, the flow figure appearing top to bottom in about 1.3s; everything else is a 0.2s hover; reduced motion shows the finished figure at once.

## Colors

The palette is a neutral ladder (white, a pale grey, a near-black) with the brand navy as the single acting colour and the brand green held back to the logo and the prompt.

### Primary
- **Brand Navy** (`navy`): The only colour that acts. Primary and small pill buttons, text links and their chevrons, the current docs page in the rail, the skip link, `::selection`, the caret and `accent-color`. The `theme-color` meta is white, not navy, so the browser chrome stays part of the ground.
- **Navy Hover** (`navy-hover`): The slight lightening a navy button takes on hover; the only hover colour change on a filled control.
- **Navy Halo** (`navy-halo`): The 3px `:focus-visible` outline at 3px offset on every focusable element on light ground, blending to about 3.5:1 against white.
- **Halo on Dark** (`halo-on-dark`): The same outline on the black band, where the navy would vanish; white at 70% so the ring reads against black and against the dark panels.

### Neutral
- **White** (`white`): The page ground, the flow figure's pills, button text on navy, the light Copy button on the black band, and tile faces when a tile sits on a grey band.
- **Band Grey** (`band-grey`): Alternating section bands, the grey tile (`tile-grey`) on a white band, docs rail hover fill, docs code blocks, blockquotes and inline code in prose.
- **Band Black** (`band-black`): The one black section, Get started in seconds. Text on it is `ink-on-dark`.
- **Dark Panel** (`dark-panel`): The flow figure's window frame, the segmented control and the command panel on the black band. Same value as `ink`, kept distinct by role: it is a surface here, not text.
- **Ink** (`ink`): Primary text everywhere on light ground, including inside tiles, pills, the command chip and the selected segment.
- **Ink Secondary** (`ink-secondary`): Subheads, tile paragraphs, term-list lines, pill-list words, the statement and note paragraphs, captions, rail and index group labels, table heads, footer copy.
- **Ink on Dark** (`ink-on-dark`): The frame title, headlines, text links, the install command and the selected segment face on dark surfaces.
- **Ink on Dark Secondary** (`ink-on-dark-secondary`): The frame subtitle, subheads and captions on the black band, unselected segment labels.
- **Hairline** (`hairline`): The 1px lines of the flow figure (pill borders, connectors, stem and bar), pill-list borders, the docs article head and foot, index group rules, prose tables and `hr`; also the thumb colour of the thin scrollbars on docs code blocks, tables and the rail, on a transparent track.
- **Hairline Soft** (`hairline-soft`): The nav's bottom edge and the footer's top edge on white.
- **Hairline Dark** (`hairline-dark`): 1px edges of the segmented control and command panel on the black band; also the footer link colour.
- **Chip Field** (`chip-field`): The quiet grey field behind the command chip on the docs index.
- **Light Button Hover** (`light-button-hover`): The grey the white Copy button turns on hover.
- **Window Bar** (`window-bar`): The 36px title bar of the flow figure's frame.
- **Traffic Lights** (`light-red`, `light-yellow`, `light-green`): The three 12px macOS window lights in the frame's bar. Decorative chrome only; never used as status colours.
- **Nav Frost** (`nav-frost`): The nav background, paired with `backdrop-filter: saturate(180%) blur(20px)`.
- **Brand Green** (`brand-green`): The logo's green, used in the stylesheet only for the `$` and `PS>` prompt of the install command. Never a button, link, heading or status.

### Named Rules
**The One Accent Rule.** The brand navy is the only colour that acts. If an element can be pressed, followed, selected or focused, it is navy; nothing decorative is navy. The brand green appears in the logo and as the install prompt and nowhere else.

**The Band Rhythm Rule.** The page is white and `band-grey` in alternation, with exactly one black band, reserved for getting started. New sections join the alternation; they do not introduce a third ground colour or a tinted band.

**The Chrome Is Not Status Rule.** The traffic lights, the window bar and the prompt colour belong to the window frame and the install command. They are never borrowed to signal success, warning or error elsewhere on the site.

## Typography

**Display Font:** Inter Variable (with the system sans-serif stack as fallback)
**Body Font:** Inter Variable (same stack)
**Label/Mono Font:** Geist Mono Variable (with ui-monospace, SF Mono, Menlo, Consolas), ligatures off

Both families are self-hosted through fontsource packages imported in the site layout. Inter runs with `cv11`, `ss01` and `ss03` enabled (single-storey a, open digits, rounder punctuation) and antialiased smoothing; `code`, `kbd` and `pre` reset `font-feature-settings` to normal so the mono face is untouched.

**Character:** One sans at three weights (600 for anything that heads, 400 for anything that explains, 500 for button labels, segmented tabs, the flow pills and the tagline) with tracking that tightens as size grows, from -0.012em in body to -0.03em at display. The monospace is the product's own voice and is set exactly as a terminal would set it: no tracking, no ligatures, one colour, one size.

### Hierarchy
- **Display** (600, clamp(2.75rem, 2rem + 3.3vw, 5rem), 1.05, -0.03em): The hero headline only, centred, max 14ch. Sentence case with a full stop.
- **Headline** (600, clamp(2.25rem, 1.6rem + 2.4vw, 3.5rem), 1.08, -0.028em): The one headline each section band carries, centred in a section head; max 18ch in the statement band. Also the docs index h1 and the not-found page's h1.
- **Subhead** (400, clamp(1.3125rem, 1.1rem + 0.7vw, 1.75rem), 1.25, -0.014em, `ink-secondary`): The explanation under a display or headline, max 48ch, centred, three lines or fewer on desktop.
- **Title** (600, 1.5rem, 1.17, -0.022em): Bento tile headings and the terms of a term list.
- **Article Title** (600, clamp(2rem, 1.6rem + 1.5vw, 2.75rem), 1.1, -0.025em): The h1 of every documentation article, over a hairline.
- **Frame Title** (600, clamp(1.5rem, 1.2rem + 1vw, 2rem), 1.1, -0.022em, `ink-on-dark`): "Your CLI" inside the flow figure's frame, over a Frame Sub at 1rem in `ink-on-dark-secondary`, 6px apart.
- **Statement** (400, clamp(1.1875rem, 1rem + 0.6vw, 1.5rem), 1.35, -0.014em, `ink-secondary`): The one paragraph of the statement band, max 46ch, closed by a tagline at 1.0625rem 500 in `ink`; also the note that follows the qualities list (`note`, max 58ch, its lead sentence in `ink` at 600).
- **Closing** (600, subhead size, body line-height, -0.014em, `ink`): One centred sentence that ends a band after a list.
- **Body** (400, 1.0625rem, 1.47, -0.012em): Default reading. Tile paragraphs and term-list lines are body size in `ink-secondary`; flow pills are body size at 500.
- **Prose** (400, 1.0625rem, 1.6): Documentation articles at max 640px, about 70 to 75 characters per line. Prose h2 1.875rem, h3 1.375rem, h4 1.0625rem, all 600 at -0.02em and 1.2; `* + *` rhythm 1.1em.
- **Pill** (400, 0.9375rem, -0.006em, `ink-secondary`): The words in the pill list; also the docs index descriptions, the article foot and prose tables.
- **Caption** (400, 0.875rem, 1.43, `ink-secondary`): Install notes. Footer copy is 0.75rem at 400 in the same colour.
- **Label** (600, 0.75rem, 0.04em, uppercase, `ink-secondary`): Only as the group heading over a list of links in the docs rail and the docs index. Never above a headline.
- **Button** (500, 1.0625rem, line-height 1): Pill button labels; the small nav pill is 0.8125rem.
- **Nav** (400, 0.875rem): Nav links at 0.82 opacity and docs rail links at 0.85 opacity (the rail tightens tracking to -0.006em).
- **Tab** (500, 0.875rem, line-height 1, -0.006em): The two segmented-control tabs on the black band.
- **Command** (Geist Mono 400, 0.875rem, 1.6, no tracking): The one mono size. The install command panel, the command chip on the docs index, and docs code blocks. Inline code in prose is 0.875em of its parent.

### Named Rules
**The Sentence Case Rule.** Every landing-page headline is a sentence: sentence case, ending in a full stop, at 600. The only uppercase on the site is the 12px group label over a list of links; it never introduces a headline.

**The Mono Is the Product Rule.** Anything the visitor would type, the install one-liner, the grammar line and every command, path, flag and `{{Token}}` in the docs, is Geist Mono with ligatures off and no tracking, at one size. Syntax highlighting is disabled in the Markdown pipeline; a command is one colour, with only the prompt stepping away from it.

**The Words Not Commands Rule.** The landing page is marketing: it carries no command, code, transcript or file list except the install one-liner and the hero's demo shell, where the commands are the visitor's own. A benefit is a sentence-case title and one grey line, and the command that proves it lives on the docs page the section links to.

## Layout

The page is a stack of full-width bands, each a `.section` padded clamp(72px, 9vw, 128px) top and bottom, alternating white and `band-grey`, ending in one black band and a hairline-topped footer. Content centres in one of two containers: `.wrap` at min(980px, 100% minus two 22px gutters) for the hero, the statement, the install band, the not-found page and the nav; `.wrap-wide` at min(1200px, same) for the term lists, the pill list, the bento and the docs. A section that is a link target (`#install`) carries `scroll-margin-top: 48px` so it stops below the sticky nav with its headline in view.

Each band opens with a centred section head at max 760px: headline, subhead at max 48ch and, on the docs index only, a command chip at `fit-content` with 8px extra above, stacked with 16px gaps and clamp(40px, 5vw, 64px) below. A band closes with either a closing line or a section link, a single centred text link clamp(32px, 4vw, 48px) below the content. The not-found page is one section head with its bottom margin removed, then the actions row, centred vertically in a section at least 60vh tall so the footer stays low.

The hero is its own rhythm: clamp(40px, 4.5vw, 72px) above the display, 20px to the subhead, 32px to the actions row (16px by 28px gaps), then clamp(40px, 4vw, 56px) to the flow figure, with clamp(64px, 8vw, 112px) below. The figure is a centred column: a pill, a 28px hairline, the 560px frame, a 20px stem, a 1px bar spanning the centres of the outer branches, 28px hairlines and a 3-column row of pills at 640px with 12px gaps (8px under 734px). The stack fits a 1280x800 viewport with the three audience pills sitting at the fold.

The bento is a 6-column grid with 16px gaps; the five tiles span 3, 3, 2, 2 and 2 so the rows read 3+3 over 2+2+2. Inside a tile content is a column with 12px gaps and the link row is pushed to the tile floor with `margin-top: auto` so a row of unequal tiles lines up. The term list is a 3-column grid at 40px by 48px gaps; its `audiences` variant narrows to the 980px container. The pill list wraps at max 780px with 8px gaps. The note and the closing line sit clamp(40px, 5vw, 56px) and clamp(40px, 5vw, 64px) under the list they follow.

The docs grid is a 240px sticky rail (top 72px, 24px between groups, 4px between links) beside an article at max 640px, with a clamp(32px, 5vw, 72px) gap and 48px/112px block padding. The docs index is an auto-fit grid of 280px-minimum columns with 40px by 48px gaps.

Three breakpoints step the page down. At 1068px (tablet) the containers drop to 692px and 980px; the bento becomes two equal columns with the 3- and 2-span tiles one column each and the last tile full width; the term list drops to two columns while `audiences` keeps its three; the docs rail narrows to 200px. Spacing steps as reused: 4, 8, 12, 16, 20, 22, 24, 28, 32, 40, 48, 56, 64px, with the three clamps above for tile padding, section-head margin and section padding.

**The One Idea Per Screen Rule.** A band carries one headline, one subhead and one proof. If a second idea needs saying, it gets its own band in the alternation, not a second headline in the same one.

**The One Pointer Rule.** Every landing-page band points into the documentation exactly once: a section link under the content, or one link per tile and a section link under the bento. The hero's pointer is the Start page beside the Install button; the install band's pointer is the pair of first-run paths on that page.

## Elevation & Depth

Depth is tonal first and cast second. Bands alternate white and grey; tiles are flat `band-grey` on the white band (`tile-grey`), or flat white on a grey band, with no border and no shadow, distinguished from the band only by tone and their 28px corners; the install controls on black are `dark-panel` with a 1px `hairline-dark` edge. Exactly one cast shadow exists on the site, under the flow figure's window frame, as the one soft shadow a product shot has under the product: a 60px blur with negative spread plus a tighter 24px blur. The nav is a frosted layer (`nav-frost` with `saturate(180%) blur(20px)`) over the content, closed by a soft hairline. Nothing glows, nothing has a hard offset shadow, no gradient appears anywhere.

### Shadow Vocabulary
- **Window** (`box-shadow: 0 30px 60px -24px rgba(0, 0, 0, 0.35), 0 8px 24px -12px rgba(0, 0, 0, 0.2)`): The flow figure's frame, and nothing else.

### Named Rules
**The One Shadow Rule.** A cast shadow belongs under the one dark object on the page, the window frame that stands for the CLI, and nowhere else. Buttons, tiles, pills, panels and the nav are flat; they separate by tone, by a hairline or by frost.

**The Flat Tile Rule.** A tile is grey on white or white on grey, no border, no shadow, no hover lift. If a tile needs more presence, give it more columns, not more depth.

## Shapes

Three radii describe nearly everything: the pill (980px) for anything pressable or badge-like (buttons, the segmented control and its tabs, the flow pills, the pill-list items, the skip link); 28px for tiles (20px under 734px); and 14px for the window frame and the install command panel. The command chip, docs code blocks and blockquotes are 12px; docs rail links 8px; inline code 6px; the focus outline rounds at 4px; the traffic lights are circles.

Borders are 1px `hairline` and appear only where tone cannot separate: around the flow pills and pill-list items, as the flow figure's connectors, under the nav, above the footer, around the dark controls on the black band, under the docs index group labels, and in docs tables and article head and foot. The flow figure's connectors are the same 1px hairline as its pill borders, so the figure reads as one line drawing with a dark frame set into it. There are no 2px borders, no outlines other than focus, and no clipped or angled shapes; the frame's bar takes the 14px radius on its top corners so it meets the frame's edge cleanly. The only icon is an 8x13 chevron drawn with a 1.6px round-capped stroke in `currentColor`, closing a text link.

## Do's and Don'ts

### Do:
- **Do** alternate white and `band-grey` bands and keep exactly one black band, for getting started (The Band Rhythm Rule).
- **Do** open every band with a centred section head: one sentence-case headline with a full stop, one subhead in `ink-secondary` at max 48ch (The One Idea Per Screen Rule).
- **Do** keep the landing page to words: a benefit is a title and a grey line, and its command lives on the docs page the section links to (The Words Not Commands Rule).
- **Do** end every landing-page band with one text link into the documentation, closed by the chevron (The One Pointer Rule).
- **Do** set the install one-liner, the grammar line and every command in the docs in Geist Mono at 0.875rem with ligatures off, one colour, the install prompt in green (The Mono Is the Product Rule).
- **Do** use the brand navy for anything that acts and nothing else; the brand green stays in the logo and the install prompt (The One Accent Rule).
- **Do** keep tiles flat, grey on white or white on grey, at 28px with no border and no shadow, with the link row on the tile floor, and vary their column span to compose a row (The Flat Tile Rule).
- **Do** reserve the cast shadow for the flow figure's window frame, the one dark object on the page (The One Shadow Rule).
- **Do** give every focusable element the 3px `navy-halo` outline at 3px offset, switching to `halo-on-dark` on the black band, give tab controls a roving tabindex with arrow-key movement, and show the finished flow figure at once under `prefers-reduced-motion`.
- **Do** make every press target at least 24px tall, as the text link, the 32px nav links and the padded footer links are, without moving the text around it.
- **Do** build a new page from the parts that exist, as the not-found page does with a section head and an actions row; the shared nav and footer come with the layout.

### Don't:
- **Don't** add a third ground colour, a tinted band, or a gradient in any fill or type.
- **Don't** put a command, code block, transcript, file list or chip on the landing page; the install one-liner is the only command it carries.
- **Don't** put an eyebrow, kicker or uppercase label above a headline; the only uppercase is the group label over a list of docs links.
- **Don't** add icons where words do the job; the 8x13 chevron closing a text link is the only icon, and it is decorative.
- **Don't** use the brand green, the traffic lights or the window bar as a button, link, heading or status colour (The Chrome Is Not Status Rule).
- **Don't** render fenced code with syntax colours or put a dark code block in the docs; docs code is dark text on `band-grey`.
- **Don't** add a hover lift, border or shadow to a tile, pill or panel; buttons darken and press, links underline, and that is the whole hover vocabulary.
- **Don't** add a second entrance animation or any scroll-driven effect; the flow figure appearing top to bottom is the only authored motion, and it never delays reading or copying.
- **Don't** use a dark hero or a neon accent; the ground is white and the hero's only dark object is the window frame.
- **Don't** let the flow figure's connectors overflow a narrow column; under 375px the branch pills wrap and the bar and drops are hidden rather than squeezed.
